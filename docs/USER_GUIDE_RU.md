# VikhmanSSH — Подробное описание функционала и руководство по использованию

## 1. Общее описание

VikhmanSSH — это настольное приложение для управления удалёнными серверами через SSH. Оно предназначено для системных администраторов, разработчиков и инженеров DevOps, которым нужен быстрый и надёжный способ подключиться к Linux- или Unix-подобным машинам, работать в удалённой оболочке, просматривать удалённые файлы, загружать и выгружать данные, редактировать текстовые документы и смотреть медиафайлы прямо внутри приложения.

Проект реализован как Qt-приложение на базе PySide6 и Paramiko. Оно поддерживает несколько параллельных SSH-сессий, многоязычный интерфейс, безопасную проверку host key и встроенный файловый менеджер с просмотром и редактированием.

Главная идея программы — удерживать пользователя в одной среде, где он может:

- подключаться к нескольким удалённым хостам,
- переключаться между активными терминалами,
- выполнять команды в удалённой оболочке,
- просматривать и изменять удалённые файлы,
- управлять каталогами и файлами,
- просматривать журналы и ошибки,
- использовать интерфейс на нескольких языках.

## 2. Основные функциональные возможности

### 2.1 Управление несколькими серверами

Приложение может одновременно поддерживать несколько удалённых соединений. Каждый сервер представлен отдельным элементом в списке серверов. В списке часто отображается состояние соединения и индикаторы статуса, что позволяет быстро понять, какие хосты онлайн, офлайн, отключены или в данный момент активны.

Типичный рабочий процесс выглядит так:

1. добавить профиль сервера,
2. указать параметры подключения,
3. выбрать режим аутентификации,
4. открыть сессию,
5. работать в терминале или файловом менеджере.

Пользователь может создавать несколько профилей для разных окружений: staging, testing, production, внутренние инфраструктуры и личные машины разработки.

### 2.2 Удалённый терминал

У каждого сервера есть собственная терминальная сессия. Терминал работает через PTY и поддерживает:

- прямую передачу ввода с клавиатуры,
- вывод с ANSI-цветами,
- изменение размера терминала,
- события мыши,
- выделение текста и поддержку копирования/вставки,
- несколько активных сессий одновременно.

Это делает работу в оболочке похожей на реальный SSH-сервер в терминальном эмуляторе. Приложение также показывает этапы SSH-аутентификации и ошибки соединения в журнале над терминалом. Это помогает диагностировать проблемы с удалённой авторизацией, SSH-конфигурацией, host key и доступом через sudo.

### 2.3 Автоматическое принятие и проверка host key

При первом подключении к неизвестному хосту приложение автоматически принимает SSH host key и сохраняет его в локальном каталоге данных приложения. Это снижает лишние шаги и позволяет быстро подключаться при первом использовании.

При последующих попытках подключения приложение сверяет сохранённый host key с фактическим ключом сервера. Если они не совпадают, соединение отклоняется. Это типичная модель TOFU (Trust On First Use): доверие к ключу возникает при первом соединении, а дальнейшие несоответствия считаются подозрительными.

Отпечаток ключа (fingerprint) отображается в журнале, поэтому пользователь может сверить его через независимый канал связи для критически важных систем.

### 2.4 Профили серверов и режимы аутентификации

Приложение хранит профили серверов в конфигурационном файле в каталоге данных пользователя. В профиль входят хост, порт, имя пользователя, а также путь к SSH-ключу или параметры парольной аутентификации. Пароли и passphrase не сохраняются в файле профиля.

Поддерживаются следующие модели аутентификации:

- SSH по паролю,
- аутентификация через SSH agent,
- использование приватного ключа по пути к файлу,
- интерактивная аутентификация при необходимости.

Пароли сохраняются в системном keyring, а не в открытом текстовом файле, если платформа поддерживает такую функциональность.

### 2.5 Файловый менеджер для удалённых файлов

Файловый менеджер работает через SFTP и позволяет пользователю:

- просматривать удалённые каталоги,
- перемещаться по папкам,
- загружать локальные файлы на удалённый сервер,
- скачивать удалённые файлы на локальную машину,
- создавать каталоги,
- переименовывать и удалять элементы,
- просматривать метаданные и содержимое каталогов.

Это особенно полезно для копирования конфигурационных файлов, журналов, скриптов, артефактов сборки и рабочих каталогов проектов.

### 2.6 Предпросмотр и открытие файлов

Приложение включает встроенный просмотрщик для нескольких типов содержимого, включая:

- изображения,
- PDF-файлы,
- аудиофайлы,
- видеоролики.

Другие типы файлов открываются во внешнем системном приложении или стандартном обработчике по умолчанию.

Режим предпросмотра скачивает временную копию удалённого файла с ограничением по размеру. В текущей реализации предел составляет 512 МБ. Это позволяет быстро просматривать большие документы и медиа без постоянного сохранения полного файла в локальном рабочем пространстве.

### 2.7 Редактор текста на удалённом узле с подсветкой синтаксиса

Приложение поддерживает редактирование текстовых файлов непосредственно на удалённом сервере. Это удобно для изменения конфигурационных файлов, shell-скриптов, YAML, JSON, Python, JavaScript и других похожих данных.

Основные функции:

- открытие файла двойным кликом,
- подсветка синтаксиса по расширению файла,
- сохранение через Ctrl+S,
- поддержка UTF-8 файлов до 2 МБ,
- проверка конфликтов до записи.

Перед сохранением приложение проверяет, не изменился ли файл на сервере после открытия. Это снижает риск перезаписи чужих изменений или обновления файла другим процессом во время работы в редакторе.

### 2.8 Режим Root / sudo для файловых операций

В файловом менеджере есть переключатель Root / sudo. При включении он запускает SFTP-сервер через sudo. Это позволяет выполнять файловые операции с повышенными привилегиями.

Поведение:

- если sudo не требует пароля, режим включается немедленно,
- если пароль нужен, приложение запрашивает пароль sudo,
- пароль не сохраняется локально,
- на удалённой системе должны быть настроены sudo и выполняемый файл `sftp-server`.

Эта возможность полезна для администраторов, которым нужно читать, редактировать или переносить файлы в системных каталогах.

### 2.9 Многоязычный интерфейс

Приложение поддерживает несколько языков интерфейса. Язык можно изменить в окне Настройки. Включены:

- арабский,
- китайский,
- английский,
- французский,
- казахский,
- русский,
- испанский.

Выбор языка сохраняется в настройках. После изменения приложение перезапускается, чтобы новый язык применился ко всем модулям.

Файлы переводов находятся в каталоге `locales/`. Каждый файл представляет собой JSON и содержит соответствие исходных русскоязычных строк и переводов на выбранный язык.

### 2.10 Хранение данных и конфигурации

Приложение хранит пользовательские данные в платформенно-зависимом каталоге:

- Windows: `%APPDATA%\ServerManager`
- macOS: `~/Library/Application Support/ServerManager`
- Linux: `${XDG_CONFIG_HOME:-~/.config}/server-manager`

Там обычно находятся:

- `servers.json` — профили серверов,
- `settings.json` — параметры интерфейса и приложения,
- `known_hosts` — доверенные SSH host key,
- учетные данные в keyring, если платформа поддерживает хранение паролей.

Такой подход позволяет приложению быть переносимым и в то же время сохранять привычное поведение для конкретной ОС.

## 3. Начало работы

### 3.1 Требования

Для запуска проекта из исходников нужны:

- Python 3.9 или новее,
- графическая сессия на Linux,
- зависимости из `requirements.txt`,
- доступ по SSH к нужным серверам.

### 3.2 Ручная установка

В корне проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

### 3.3 Скрипты запуска

В репозитории есть скрипты запуска и сборки:

- Linux/macOS: `./run.sh`
- Windows: `run.bat`

Эти скрипты при необходимости создают виртуальное окружение и устанавливают зависимости. Это упрощает первое подключение и гарантирует, что приложение работает в корректной среде Python.

### 3.4 Автономная сборка

Для сборки автономного дистрибутива:

- Linux/macOS: `./build.sh`
- Windows: `build.bat`

Готовая сборка обычно создаётся в `dist/VikhmanSSH` (на macOS также может появиться bunde `VikhmanSSH.app`). Это полезно, когда приложение нужно раздавать пользователям без установки Python и зависимостей на целевой машине.

> Важно: сборку для конкретной платформы следует выполнять на этой же платформе. PyInstaller не умеет кросс-компилировать между операционными системами.

## 4. Типичный сценарий работы

### 4.1 Создание профиля сервера

В основном окне приложения можно добавить новый профиль сервера:

- имя подключения,
- hostname или IP-адрес,
- SSH-порт,
- имя пользователя,
- путь к SSH-ключу или способ паролей,
- дополнительные параметры.

Профиль сохраняется локально для дальнейшего использования.

### 4.2 Подключение к серверу

После создания профиля пользователь может открыть соединение. Во время подключения приложение выполняет SSH-рукопожатие, проверяет host key и показывает этапы аутентификации в журнале.

Если ключ сервера новый, он принимается и сохраняется в локальном хранилище host key. Если ключ уже известен, но изменился, соединение отвергается.

### 4.3 Работа в терминале

После подключения пользователю открывается удалённая оболочка. Команды передаются напрямую на сервер, а вывод отображается в терминальном интерфейсе. Наличие ANSI-цветов, изменения размера PTY и событий мыши делает опыт очень близким к обычному терминальному эмулятору.

Можно держать одновременно несколько удалённых терминалов открытыми и переключаться между ними через список серверов.

### 4.4 Работа с удалёнными файлами

Переходя на вкладку Файлы для подключённого сервера, пользователь может:

- открывать удалённые каталоги,
- загружать локальные файлы,
- скачивать данные с сервера,
- создавать папки,
- удалять или переименовывать файлы,
- проверять файлы перед загрузкой,
- открывать текстовые документы во встроенном редакторе,
- просматривать изображения, PDF, аудио и видео.

### 4.5 Использование режима Root / sudo

Когда файловая система требует административного доступа, можно включить Root / sudo. Это полезно для редактирования системных файлов или перемещения данных в защищённые каталоги. Использовать эту функцию следует только при наличии явного разрешения и законной необходимости.

## 5. Примечания по безопасности

Хотя приложение рассчитано на удобство и продуктивность, оно работает с привилегированными инфраструктурными ресурсами. Пользователю стоит помнить о следующих принципах:

- проверяйте fingerprint хоста перед тем, как доверять серверу,
- не храните конфиденциальные данные в обычных текстовых конфигурационных файлах,
- защищайте локальные каталоги данных приложения,
- по возможности используйте SSH-ключи вместо паролей,
- осторожно проверяйте требования sudo перед включением административного SFTP-режима,
- для production-систем используйте только доверенную и проверенную инфраструктуру.

Приложение следует минималистичной философии безопасности: оно не сохраняет пароли в профиле сервера, использует keyring ОС, когда это возможно, и сверяет host key при повторных подключениях.

## 6. Устранение неполадок

### Проблема: приложение не запускается

Возможные причины:

- не установлены зависимости Python,
- на Linux нет графической сессии,
- отсутствует или повреждён виртуальный environment,
- ОС не видит необходимые библиотеки GUI.

Решение:

- установите зависимости через `python -m pip install -r requirements.txt`,
- запускайте приложение в GUI-сессии,
- проверьте совместимость версии Python,
- используйте скрипты запуска проекта для автоматического создания среды.

### Проблема: соединение отклоняется

Возможные причины:

- неправильное имя пользователя или пароль,
- неверный путь к SSH-ключу,
- не настроен SSH agent,
- несовпадение host key,
- SSH-сервис не запущен на удалённой машине.

Решение:

- проверьте учётные данные,
- сравните fingerprint host key,
- убедитесь в корректности метода SSH,
- просмотрите журнал для ошибок SSH handshake.

### Проблема: операции с файлами завершаются с ошибкой прав доступа

Возможные причины:

- у учётной записи нет прав на целевую папку,
- sudo не настроен,
- на сервере нет исполняемого файла `sftp-server`.

Решение:

- при необходимости включите режим Root / sudo,
- проверьте доступ к sudo,
- убедитесь, что на удалённой системе доступен `sftp-server`.

### Проблема: большие файлы не показываются в предпросмотре

Возможные причины:

- размер файла превышает лимит предпросмотра,
- тип файла не поддерживается встроенным просмотрщиком,
- ограничения по权限 или передаче данных блокируют просмотр.

Решение:

- при необходимости используйте локальную файловую систему или отдельный просмотрщик,
- ограничьте размер файла в пределах лимита,
- скачайте файл и откройте его в другом приложении, если формат не поддержан.

## 7. Поддерживаемые платформы и замечания по окружению

Приложение рассчитано на работу на Windows, macOS и Linux. В проекте есть shell-скрипты для упрощения установки и сборки. Для production-релизов наиболее надёжно собирать приложение на целевой ОС и распространять именно готовый bundle.

Поскольку программа использует Qt и графический интерфейс, её лучше запускать в пользовательской сессии с доступом к дисплею. На Linux для открытия окна приложения необходима GUI-сессия.

## 8. Итог

VikhmanSSH объединяет в себе основные возможности, необходимые для практического управления удалённой рабочей станцией:

- интерактивный SSH-терминал,
- несколько активных сессий,
- передача и управление файлами,
- редактирование удалённых файлов,
- предпросмотр медиа,
- проверка host key,
- многоязычность,
- интеграция безопасной аутентификации.

Это делает программу полезной для повседневного администрирования, удалённой отладки, изменений конфигурации и рабочих процессов, в которых нужно быстро получить доступ к серверу без отдельного терминального эмулятора или отдельного клиента для передачи файлов.
